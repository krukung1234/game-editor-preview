แก้จากโค้ดปัจจุบันของ repository `krukung1234/game-editor-preview` commit `696debf` บน branch พัฒนา `development/mini-city-editor-ux` โดยต่อยอด Editor เดิม ไม่สร้างระบบใหม่ ไม่แก้ Firebase/Firestore และไม่ได้ commit/push/deploy

## สิ่งที่ตรวจพบและแก้ไข

### แยกการเปลี่ยนชั้นกับการเลือกรูป

listener เปลี่ยนระดับชั้นเดิมไม่ได้เรียก file input.click() โดยตรง แต่ส่วนรูปใช้ label ครอบทั้งภาพ ข้อความ และ input type=file ทำให้พื้นที่นอกปุ่มเลือกไฟล์ก็เปิดหน้าต่างไฟล์ได้ จากภาพเพียงอย่างเดียวไม่สามารถยืนยันเส้นทาง event ที่เกิดบนเครื่องผู้ใช้ได้ จึงแก้การเชื่อม DOM ให้แยกจากกันชัดเจนและทดสอบเหตุการณ์ filechooser จริง:

- ช่องข้อความ/Dropdown ใช้ label ที่ระบุ for ตรงกับ id ของช่องนั้นเพียงช่องเดียว
- ช่องไฟล์รูปซ่อนไว้โดยไม่อยู่ภายใน label และไม่ใช้ delegated click หรือ onchange ของช่องอื่นไปเปิดไฟล์
- เปิดรูปได้จากปุ่ม **เลือกไฟล์** ของกล่องภาพนั้นเท่านั้น รวมถึงกดปุ่มด้วยคีย์บอร์ด
- การคลิกภาพหรือคำบรรยายภาพไม่เปิดไฟล์ การเปลี่ยนชั้นแก้เฉพาะค่า grade
- เมนู **นำเข้า JSON** ยังเปิดตัวเลือกไฟล์ JSON ตามหน้าที่เดิม แยกจากการเลือกภาพ
- ผลอ่านไฟล์แบบ asynchronous จะไม่เขียนลงฉบับเก่าหลังมีการนำเข้าหรือเปลี่ยนฉบับข้อมูล

### รักษาข้อมูลหลังบันทึก

พบข้อผิดพลาดเพิ่มเติมใน save(): เปลี่ยน draft เป็นออบเจ็กต์ใหม่ แต่ handler ของคำถาม/ตัวเลือกที่แสดงอยู่ยังจับออบเจ็กต์เก่าไว้ ทำให้การแก้ต่อหลังบันทึกอาจไม่เข้า draft ที่จะบันทึกรอบถัดไป แก้ให้ตรวจและบันทึกสำเนาที่ผ่าน schema โดยคงออบเจ็กต์ที่ฟอร์มใช้งานอยู่ ไม่รีเซ็ตค่าหรือสร้างฟอร์มใหม่ขณะบันทึก

### ปรับหน้าต่างเดิม

- ปุ่มหลักล่างเหลือ 3 ปุ่ม: **▶ ทดลองเล่น**, **💾 บันทึกเกม**, **⋯ เพิ่มเติม**
- ในเมนูเพิ่มเติมมี **ดูตัวอย่างข้อมูล**, **ส่งออก JSON**, **นำเข้า JSON**, **คืนค่าเกมต้นฉบับ** ครบ
- หัวหน้าต่าง/สถานะและแถบปุ่มอยู่กับที่ เลื่อนเฉพาะเนื้อหาตรงกลาง คืนการเลื่อนหน้าหลักทันทีเมื่อปิด
- เมนูรองใช้คีย์ลูกศร, Home/End, Escape และปิดเมื่อกดนอกเมนูได้ Escape ในเมนูไม่ปิด Editor
- ยังคงปุ่ม × ด้านบนและ Escape สำหรับปิด Editor มีการยืนยันเมื่อมีข้อมูลที่ยังไม่บันทึก
- ปุ่มเลื่อนขึ้น/ลงและลบภารกิจกะทัดรัด ลบภารกิจต้องยืนยัน ยกเลิกแล้วข้อมูลไม่เปลี่ยน และยังห้ามลบจนไม่มีภารกิจในด่าน
- เพิ่มภารกิจโดย clone โครงสร้างด่านเดิม ใช้ id ใหม่และคงตัวเลือก/กติกาเดิม ตรวจ schema ก่อนบันทึก/ทดลองเล่น แผนที่ช่วยเมืองยังจำกัด 6 จุด

### ภาพในตัวแก้ไข

- รองรับเส้นทางรูปเดิมแบบ `assets/...` โดยแปลงให้ชี้ไปยัง `games/AR mini city/assets/...` อย่างชัดเจน รวมทั้งเส้นทางเดิมที่มี prefix อยู่แล้ว
- ภาพคำถาม/ตัวเลือกที่ยังไม่มีภาพแสดงภาพสำรองพร้อมคำว่า “ยังไม่ได้เลือกภาพ”
- หากภาพโหลดไม่ได้ แสดงภาพสำรองและข้อความแจ้ง ไม่เปลี่ยน URL ที่บันทึกไว้เป็นภาพสำรองอย่างเงียบ ๆ
- อัปโหลดใหม่ได้ แยกสถานะจากภาพว่าง และป้องกันการวนโหลดภาพสำรองไม่สิ้นสุด
- ภาพสำรองนี้ใช้ใน Editor เท่านั้น ไม่เปลี่ยน renderer หรือกติกาของเกมต้นฉบับ

## ผลทดสอบ

### การเลือกชั้นและไฟล์ (Chrome headless)

- เปลี่ยนครบ 15 ระดับ อนุบาล 1 ถึง ม.6 รวมถึงเลือกผ่านเมาส์/คีย์บอร์ด: **filechooser 0 ครั้ง**
- เทียบข้อมูลที่บันทึกก่อน/หลังเปลี่ยนชั้น พบเปลี่ยนเฉพาะ grade คำถาม ตัวเลือก ภาพ ชื่อ และหัวข้อคงเดิม
- คลิก caption/รูปไม่เปิด filechooser
- ปุ่มเลือกภาพหน้าปก/คำถาม/ตัวเลือก และนำเข้า JSON เปิด chooser เฉพาะเมื่อสั่ง มีเหตุการณ์ตามที่คาด 4 ครั้ง แยกชนิดช่องถูกต้อง
- เลือกภาพตัวเลือกด้วย Enter ได้ ลบภาพแล้วไม่เปิดไฟล์และแสดงสถานะภาพว่าง
- หลังบันทึกครั้งแรก แก้คำถามและตัวเลือกแล้วบันทึกซ้ำ ข้อมูลรอบใหม่ถูกเก็บจริง

### ปุ่มและข้อมูล

- ตรวจปุ่มหลัก 3 ปุ่ม รายการรอง 4 รายการ กดดูข้อมูล ส่งออก ดาวน์โหลด JSON นำเข้าผ่าน chooser และคืนค่าต้นฉบับผ่าน
- ทดสอบยืนยัน/ยกเลิกลบภารกิจ การเลื่อนขึ้นแล้วลง การเพิ่ม/ลบตัวเลือก การเพิ่มภารกิจในทุกด่าน และการปฏิเสธจุดที่ 7 ของด่านช่วยเมือง
- รูปจาก assets เดิมโหลดได้ ภาพเสียใช้ fallback ที่โหลดสำเร็จ โดย URL ข้อมูลเดิมไม่ถูกแก้
- ทดสอบปิด/เปิดใหม่ คืนค่าการเลื่อนหน้าหลัก และยกเลิกปิดเมื่อมีฉบับยังไม่บันทึกโดยข้อมูลไม่หาย
- ทดสอบการนำเข้า JSON ผิด schema พื้นที่ localStorage เต็ม และข้อมูลที่มีอักขระ HTML ผ่านชุดทดสอบเดิม

### Layout และเล่นจริง

- ตรวจ 1440×1000, 768×1024, 375×812, 320×568 และแนวนอน 844×390: หัวและแถบปุ่มไม่เคลื่อนตามเนื้อหา ปุ่มไม่ซ้อนกันและไม่มีแถบเลื่อนแนวนอนใน Editor
- เล่น Mini City ด้วยข้อมูลใหม่ครบ 5 มินิเกม ทั้งคอมพิวเตอร์และมือถือจำลอง ตรวจคำตอบผิด/ถูกและคะแนน ผ่าน
- รอบตรวจคะแนนคอมพิวเตอร์: แยก 1/2, จับคู่ 1/2, จัดกระเป๋า 2/3, ซื้อของ 4/9, ช่วยเมือง 1/2 ตรงกับคำตอบที่ทดสอบ
- ทดสอบกล้องถูกปฏิเสธ กล้องจำลองและผลมือจำลองค้าง 3 วินาทีผ่านกลไกเดิมได้
- Prompt เดิม: ประกอบข้อความ คัดลอกจริง/fallback เปิด–ปิด/focus ผ่าน; VIP, ค้นหา, หมวดหมู่และการ์ดเดิมผ่าน
- JavaScript/console errors = 0 และ external writes = 0; syntax และ `git diff --check` ผ่าน

ข้อจำกัด: Firestore ใช้ข้อมูลจำลอง มือถือใช้ viewport จำลอง และกล้อง/ผลตรวจมือเป็นข้อมูลจำลอง ควรตรวจบนอุปกรณ์จริงก่อนเผยแพร่ การทดสอบ filechooser ใช้เหตุการณ์จาก Chrome ไม่ได้ถ่ายภาพหน้าต่าง Open ของระบบปฏิบัติการ

ดูผลละเอียดใน `mini-city-ux-behavior-results.json`, `ux-full-game-test-results.json` และ `ux-prompt-regression.json`

## วิธีทดสอบด้วยตนเอง

1. เปิดรุ่นใหม่ผ่าน localhost/HTTPS เข้าสู่ VIP แล้วกดปรับแต่ง Mini City ต้องเห็นเลข **20261016-5**
2. กรอกชื่อ/คำถาม เลือกชั้นหลายครั้ง ต้องไม่เปิดไฟล์และค่าที่กรอกยังอยู่
3. กด **เลือกไฟล์** ในภาพหน้าปก คำถาม และตัวเลือกแยกกัน ตรวจว่าภาพไปอยู่ในช่องที่กด
4. บันทึก แล้วแก้คำถาม/เฉลยอีกครั้ง บันทึกซ้ำและเปิดกลับมาตรวจ
5. เลื่อนเนื้อหาลงสุด ตรวจว่าหัวกับสามปุ่มหลักยังอยู่ เปิดเมนูเพิ่มเติมและลองครบทั้ง 4 รายการ
6. เพิ่ม เลื่อน และลบภารกิจ ลองยกเลิกยืนยันลบ ตรวจว่าข้อมูลไม่เปลี่ยน
7. ทดลองเล่น ตรวจคำถาม เฉลย ภาพและคะแนนใหม่ แล้วลองมือถือและกล้องจริง

## นำไปใช้

แตก ZIP และคัดลอกทั้ง 5 ไฟล์ตามตำแหน่งเดิมใน repository **game-editor-preview** บน branch พัฒนา ไม่คัดลอกไปเว็บไซต์หลัก รุ่นนี้ไม่ต้องแก้ไฟล์เกม

หากใช้ Git ด้วยตนเอง ตรวจ remote/branch/diff ก่อน:

```powershell
git remote -v
git branch --show-current
git diff --check
git add -- index.html css/style.css js/game-editor.js js/game-adapters.js images/editor-image-placeholder.svg
git commit -m "Fix Mini City editor file selection and simplify editor actions"
git push -u origin development/mini-city-editor-ux
```

หากใช้ checkout เดิมของคุณ ให้สร้าง branch นี้จากรุ่นล่าสุดก่อนคัดลอกไฟล์ คำสั่ง commit/push ข้างต้นไม่ได้ถูกดำเนินการให้อัตโนมัติ

หลังอัปโหลดให้ตรวจว่า GitHub Pages เผยแพร่จาก branch ที่มีโค้ดรุ่นนี้ หรือใช้ PR/ขั้นตอนเผยแพร่ของ repository preview ด้วยตนเอง รอ deployment สำเร็จแล้วกด Ctrl+Shift+R ตรวจ footer และ Editor เป็นรุ่น 20261016-5

HTML ต้องเรียก `css/style.css?v=editor-20261016-5`, `js/game-editor.js?v=editor-3` และ `js/game-adapters.js?v=editor-3` หากยังได้รุ่นก่อน ให้ตรวจ HTML response, source branch และ deployment ไม่ใช่แก้ข้อมูล Firebase
