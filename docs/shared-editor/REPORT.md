## สิ่งที่ทดสอบจริง

- Mini City: แก้ข้อมูลส่วนตัว เล่นครบทั้ง 5 เขต คะแนน/เฉลย/ภาพ/ชื่อเขตและข้อความผ่านจริงทั้ง Preview และ ZIP, ตรวจ CRC/แตก ZIP, โมเดล MediaPipe จริงผ่านกล้องจำลองและเล่นออฟไลน์ผ่าน localhost, ผู้ใช้สองบริบทแยกกัน, เปิดใหม่กลับต้นฉบับ
- แม่ กบ / แม่ กก / ตีตัวตุ่น: แก้คลังคำเป้าหมายและคำลวงผ่าน UI ตรวจตอบถูก +1/ผิด 0 เล่นจนหมดเวลาและตรวจคะแนนสรุป ทั้ง Preview และ ZIP; แม่ กบมีการตรวจโหมดจีบนิ้วเพิ่มเติมด้วย SDK จริงและพิกัดมือจำลองที่ callback เดิม
- AR_Opposite: แก้คู่คำ เล่นครบ 20 ข้อ ตรวจถูก/ผิดและคะแนนสรุป 19/20 ทั้ง Preview และ ZIP; ทดสอบภาพอัปโหลด 41 รายการกับภาพที่แสดงในเกมและ ZIP
- Prompt: ทดสอบทั้ง 31 เกม การเริ่มจากต้นฉบับ คืนค่า AI on/off คัดลอกและ fallback และ Responsive โดยไม่เปลี่ยนระบบ Prompt
- Editor: ทดสอบ X/Escape/ป๊อปอัปยืนยัน/คีย์บอร์ด Focus/เปิดปิด 15 รอบโดย listener ไม่เพิ่ม; รูปแบบ 3 แท็บ/3 ปุ่มและไม่มี horizontal overflow ในขนาดมือถือ แท็บเล็ต คอมพิวเตอร์
- ตรวจ syntax JavaScript และตรวจว่าไฟล์เกมต้นฉบับ/Admin/config ไม่มี diff

ข้อจำกัดการทดสอบ: กล้องเป็นกล้องจำลองของ Chrome แต่โหลด JS/WASM/โมเดลจริง มือถือและแท็บเล็ตเป็น viewport จำลอง ไม่ได้ทดสอบอุปกรณ์จริงหรือ Safari/iOS ทุกเวอร์ชัน ไม่อ้างว่าทดสอบเกมที่ปิดปุ่มผ่านแล้ว

## ขอบเขตและข้อจำกัด

- เกมตีคำยังใช้กติกา/คำอธิบายหลักของมาตราตัวสะกดเดิม แก้คลังคำภายใต้กติกานั้น ไม่ได้แปลงทุกวิชาโดยอัตโนมัติ จำนวนคำและจังหวะเกมคงเดิม
- แม่ กกและตีตัวตุ่นใช้ภาพกล้องตามต้นฉบับ ไม่ได้เพิ่ม Hand Tracking ให้เกมที่เดิมไม่มี แม่ กบคงโหมดจีบนิ้วเดิม
- AR_Opposite คงรหัสคู่ จำนวนคู่และกลไกสะสมเดิม แก้ข้อความและรูปประจำคู่/ภาพปกได้
- รูปที่มีตัวหนังสือฝังต้องเปลี่ยนรูปเอง โปรแกรมเปลี่ยนข้อความภายในรูปไม่ได้ แผ่น sprite ต้องรักษาขนาด/ตำแหน่งช่องเดิม ภาพวาดด้วย CSS/Canvas ไม่มีช่องอัปโหลดที่อ้างว่าจะแก้ภาพนั้นได้
- หัวข้อ/วิชา/ชั้นและคำแนะนำเพิ่มเติมของ Adapter ทั่วไปแสดงในแถบข้อมูลบทเรียนทุกหน้า ส่วนคำถาม/คำตอบผูกกับข้อมูลเกมจริง ไม่แทนที่เกมด้วยหน้าตัวอย่าง ข้อความกติกาที่ไม่มีช่องแก้ยังเป็นต้นฉบับ
- ข้อมูลแก้ไขและความคืบหน้าใน Preview เป็น memory ของรอบนั้น ไม่มี draft ถาวร ไม่มี localStorage draft ปิดแล้วเปิดใหม่กลับต้นฉบับ รีโหลดทำให้ข้อมูลชั่วคราวหายตามข้อกำหนด
- ZIP ต้องแตกครบและเปิดผ่าน localhost หรือ HTTPS เพื่อใช้กล้อง/โมเดล การเปิด file:// อาจเริ่มเกมที่บังคับกล้องไม่ได้ ไม่อ้างว่าใช้ localStorage แชร์ข้ามเครื่องได้
- Preview ต้องใช้อินเทอร์เน็ตสำหรับ CDN ตามต้นฉบับ ZIP ของเกมที่รับรองรวมโมเดล/ไฟล์จำเป็นไว้แล้ว เสียงพูดขึ้นกับเสียงในเครื่อง ขนาด ZIP อาจหลายสิบ MB เพราะคงทรัพยากร AR
- เกมที่ยังปิดปุ่มต้องตรวจ Adapter/กติกา/ทรัพยากรและทดสอบจนจบกับ ZIP ก่อนตั้ง qualification=complete ห้ามเพียงเปลี่ยน enabled=true

## ลดโค้ดซ้ำและการโหลด

- UI, ฟอร์ม, Working Copy, validation helpers, preview transport, composer และ ZIP ใช้โค้ดกลาง ไม่มี Editor แยก 31 ชุด
- รายการเริ่มต้นมีเพียง metadata ขนาดเล็ก โหลด Blueprint และภาพเฉพาะเกมที่เปิด ภาพใน Editor แบ่งหน้า ครั้งละ 12 ภาพ
- คลังข้อความเริ่มต้นอ่านจาก Blueprint โดยไม่เก็บ values ซ้ำ; ภาพฝังแยกเป็นไฟล์ตาม SHA-256 และใช้ร่วมกัน
- โหลดตัวสร้าง package แบบ dynamic import เมื่อกดดาวน์โหลดเท่านั้น ดาวน์โหลดทรัพยากรพร้อมกันสูงสุด 4 งาน ไม่สร้าง ZIP ล่วงหน้า
- ใช้ cache ของ resource ที่อ่านแล้ว ปล่อย Blueprint/DOM/Object URL เมื่อปิด และหยุด MediaStream/โมเดลอย่างชัดเจนเมื่อออกจาก Preview ไม่มี listener ปิด Editor จาก blur/focus/visibilitychange
- ตรวจ SHA-256 ของ HTML และสคริปต์ก่อนใช้ตำแหน่ง AST หาก source เปลี่ยนรุ่นจะปฏิเสธแทนแก้ผิดตำแหน่ง
