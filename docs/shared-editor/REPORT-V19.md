## ขอบเขตการทดสอบและข้อจำกัด

- UI/การคืนค่า/ปิดแล้วเริ่มต้นใหม่/ฟิลด์ข้อมูล ตรวจครบ31เกม (Mini Cityแยกชุดทดสอบ และNative30เกม) ข้อมูลอยู่ในWorking Copy ไม่บันทึกร่าง
- Preview/ZIP: native engine เดิม คำถามถูก/ผิด คะแนนและลำดับด่านตามหลักฐานรายเกม ไม่ตั้งค่าคะแนนหรือปลดล็อกด่านโดยตรง อินพุตบางเกมเรียก callback เดิมด้วยวัตถุหรือพิกัดจริง ไม่เท่ากับทดสอบท่ามือคนจริง
- ตรวจเปลี่ยนภาพอย่างน้อยหนึ่งภาพต่อทุกเกมที่มีภาพไฟล์ ทั้ง Preview และZIP CRC/โหลดภาพหลังแตกไฟล์ โดยบล็อกเว็บภายนอก เกมที่ไม่มีภาพไฟล์ไม่เพิ่มความสามารถเทียม
- ตรวจการส่งค่าฟิลด์ทุกชนิด text/select/boolean ไปnative bindingsครบเส้นทาง ส่วนตัวเลข/ตารางตรวจตามกติกาเฉพาะเกม ไม่อ้างว่าทดสอบทุกชุดคำถามที่ผู้ใช้สามารถกรอกได้
- เกมสร้างโจทย์คณิตศาสตร์และเขาวงกตไม่ได้มีชุดคำตอบปรนัยทั่วไป ใช้ค่าที่ต้นฉบับรองรับ ไม่สร้างโจทย์เทียม
- กล้องใช้Chrome/MediaPipeจริงกับกล้องจำลอง ต้องทดสอบมือ/หน้าและอุปกรณ์จริงเพิ่มเติม ไม่รับรองกล้องบนfile:// ใช้HTTPS/localhostและอนุญาตกล้อง เสียงพูดขึ้นกับเสียงที่มีในระบบ
- ภาพสำเร็จรูปที่มีข้อความฝังไม่เปลี่ยนข้อความอัตโนมัติ ภาพspriteต้องรักษาขนาดและตำแหน่งช่องเดิม

## หลักฐานการซิงก์เฉลย

เกมคอมพิวเตอร์ครบ8โหมดผ่านด้วยคะแนน39/40ในPreviewและZIP ส่วนการทดสอบเพิ่มแก้ตัวเลือกและตำแหน่งคำตอบจริงให้ข้อความเฉลยเปลี่ยนเป็นคำตอบใหม่ แล้วทดสอบตอบผิด0คะแนนและตอบถูก1คะแนนทั้งPreviewและZIP ผ่าน โดยไม่เขียนค่าคะแนนโดยตรง

เกมแม่เหล็กสลับเฉลยวัตถุจริงหนึ่งคู่ผ่านUI รักษาจำนวน8ชิ้นต่อกลุ่ม แล้วเล่นทั้งสองภารกิจครบด้วยคะแนน13ตามกติกาเดิม ทั้งPreviewและZIP ผ่าน

เพิ่มเติม: โหมดมือของแม่กบผ่านทั้งPreviewและZIP โหลดโมเดลMediaPipeจริงกับกล้องจำลอง แล้วส่งlandmarkสังเคราะห์ผ่านcallbackเดิมเพื่อตรวจจีบนิ้วเลือกถูก/ผิดและจบเวลาตามเกมเดิม คะแนน1ตรงกัน ไม่ใช่การทดสอบมือคนจริง เกมแม่กกและตีตัวตุ่นต้นฉบับใช้กล้องเป็นฉากหลัง ไม่มีHandTracking จึงไม่เพิ่มระบบที่ต้นฉบับไม่มี

ไฟล์tools/verify-shared-editor.cjsเพิ่มการตรวจความสัมพันธ์ฟิลด์ข้อความเฉลยกับตำแหน่งคำตอบและตัวเลือก เพื่อป้องกันmetadataอ้างฟิลด์ผิด
